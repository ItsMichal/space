# Migration plan: Next.js (OpenNext) to React Router 7 + Vite, prerendered, plain Worker

Status: Phase 0 (inventory and plan). Branch `michal-rr7-migration`. Owner request: same site, same URLs, same look and behaviour,
simpler stack. This file is written before any porting code and updated as decisions change.

## 0. Verdict on blockers

No hard blocker for React Router 7 prerendering. Evidence: a throwaway spike (outside the repo) with
`react-router.config.ts` `{ ssr: false, prerender: [...] }`, a route `loader` that reads the filesystem with `node:fs`,
a resource route returning XML, a plain-text resource route and a `meta` export containing `script:ld+json`, built with
`react-router build` (react-router 7.x, vite 7.3.7, Node 22.3). Result:

- HTML written per path (`/posts/a` to `posts/a/index.html`), loader output baked in; loader code is not in the client bundle.
- Loader data is also written as `<path>.data` for client-side navigation (static files, served by assets).
- Resource routes (`/feed.xml`, `/robots.txt`) are prerendered to the exact path, no extension needed.
- The server bundle is deleted after prerender (`ssr:false`): the output is `build/client` only.
- `<meta>`/`<link>` come from `meta`/`links` exports, so every tag the site emits can be reproduced (see section 3).

Known soft spots (each has a mitigation below): binary resource routes (PNG share cards) cannot be written by the prerender
step, so they are generated by a build script; extensionless files (`/opengraph-image`) need a Content-Type from the Worker;
Node here is 22.3 while vite 7 wants >= 22.12 (works, warns; CI uses `node-version: 22` so it gets a current 22).

### 1.2 Metadata, feeds, share cards

- `lib/seo.ts` returns Next `Metadata` objects. It stays unchanged (type-only import of `next`; kept as `import type` and the
  `next` package is retained as a type-only dev dependency until the last commit, then replaced by a local `Metadata` type in
  `lib/meta-types.ts`). New `lib/head.ts` converts a `Metadata` into RR7 `meta()`/`links()` arrays in the order Next emits them:
  title, description, robots, canonical, alternates (`rss`, `feed+json`), openGraph (`og:*`), twitter (`twitter:*`), icons,
  `theme-color` per media, `color-scheme`, viewport. One converter, one place, covered by a golden test against the Next output.
- JSON-LD: the existing `JsonLd` component (a `<script type=application/ld+json>` in `<body>`, inside the page) is kept as is, so the
  position matches today. Not using `script:ld+json` in `meta` (it would move the tag into `<head>`).
- Share cards: Next serves `/opengraph-image` and `/twitter-image` per route with a content-hash query in the meta tag
  (`?<hash>`). The new build writes the PNGs to `build/client/_og/<route>.png` and the Worker serves them at the same extensionless
  URLs with `Content-Type: image/png`. The meta tags reference the same URLs (the golden tag values are compared; if the hash query is part of
  today's tags the new build produces a content hash the same way so the tag shape is unchanged). `lib/og.tsx` keeps its JSX; only the
  `ImageResponse` import changes to a local `lib/og-render.ts` (satori + @resvg/resvg-js, Node only, never bundled into the client).
- Feeds, sitemap, robots, manifest: same builder functions, wrapped in resource-route loaders returning `Response` with today's content types.
  `lastmod`/build dates come from content, so byte-compare works.

### 1.3 Redirects and host handling

- `content/redirects.json` (19 targets, 59 sources including `/opengraph-image` and `/feed.xml` variants) via `lib/redirects.mjs` `buildRedirects()` (unchanged,
  tests unchanged). Next serves them as 308 with `Refresh`-less `Location`. In the new Worker `worker/redirects.ts` builds a `Map` from the same function at build time
  (generated `worker/redirects.generated.ts` by `scripts/build-worker-redirects.mjs`, committed output ignored) and answers 308 before anything else.
  `_redirects` for Workers static assets is rejected: it cannot be combined with the host redirect and the 59-rule file would be a second source of truth.
- Host redirects (`worker/host.ts`, `canonicalRedirect`, `isPreviewHost`) are reused unchanged.
- Trailing slash: Next (`trailingSlash:false`) 308-redirects `/about/` to `/about`. The Worker normalises (308 to the slash-less path, query kept) and asks
  assets for `/about` which resolves to `about/index.html` (`html_handling: "drop-trailing-slash"`). Verified in the parity harness (redirect rows).
- 404: Worker calls `env.ASSETS.fetch`; on 404 it fetches `/404/index.html` and responds with that body and status 404 (`not_found_handling: "none"` so assets does not
  invent its own).

### 1.4 Headers and caching

`public/_headers` stays (Workers assets reads it from the asset directory). Today it covers `/_next/static/*` (immutable); the new build's hashed files live under
`/assets/*`, so the rule is changed to `/assets/*` (immutable) and the `/media`, `/botanical`, `/textures`, `/motion` rules are unchanged. `*.workers.dev` `X-Robots-Tag: noindex`
is already in `worker/index.ts` and is kept. HTML responses: assets default (ETag, `Cache-Control: public, max-age=0, must-revalidate`); compared against Next's `s-maxage` header in the harness
(intentional difference if it differs, recorded in the report).

### 1.5 Images

`scripts/build-images.mjs` writes `public/media/_v/*` (AVIF/WebP + manifest at `lib/media/manifest.json`) and `_og/*`. Components use the site's own `Picture`/`Zoomable`
(via `lib/media/getImageInfo`), not `next/image`: they stay byte-identical. The single `next/image` import is in a dev-only page (checked; replaced with a plain `<img>` in the dev page adapter).
Risk: `manifest.json` (about 180 KB) is imported by `getImageInfo`, which now runs on the client too (components hydrate). Measured in Phase 3; mitigation if it is large: loaders attach the needed
`ImageInfo` entries and `Picture` reads a context first (new file, component unchanged apart from one import).

### 1.6 Fonts

`next/font` is replaced by files in `public/fonts/` and one `app/styles/fonts.css`:
- Michelangelus Regular/Italic woff2: copied from `app/fonts/` (same files), `@font-face` with `font-display: swap`, family `__Michelangelus`-style name preserved as a variable `--font-display-face`.
- Newsreader (variable, opsz axis, normal+italic, latin and latin-ext) and IBM Plex Mono 400/500 (latin, latin-ext): the exact woff2 files Google serves are committed (both OFL). `unicode-range` blocks copied from the Google CSS.
- Next's generated fallback (`size-adjust`, `ascent-override` etc. for Times New Roman, `adjustFontFallback`) is reproduced by reading the values out of the golden build's CSS and writing the same `@font-face` fallback blocks by hand; CLS is measured old vs new in Phase 3.
- `<link rel=preload as=font crossorigin>` for the same subset files Next preloads (taken from the golden HTML), emitted via root `links`.
- CSS variables `--font-newsreader`, `--font-plex-mono`, `--font-display-face` are kept; `html` class names set by Next (`display.variable serif.variable mono.variable`) are replaced by equal CSS in `:root`.

### 1.7 CSS

Tailwind 3.4 + PostCSS stay (Vite picks `postcss.config.js` and `tailwind.config.js` up unchanged). Global CSS import order in `layout.tsx` (`globals.css`, `craft.css`, `type.css`, `card.css`, `transition.css`) is reproduced in `root.tsx` imports in the same order; component CSS imports (`about.css`, etc.) remain side-effect imports in components, which Vite handles. Tokens CSS (`app/styles/tokens.css`) is generated from `@space/tokens` by `npm run tokens`, unchanged. Risk: CSS ordering differs between Next (per-chunk) and Vite (per-route chunks); pixel diff catches it.

### 1.8 Client/server split

70 files carry `'use client'`; under RR7 the directive is inert (harmless string), everything hydrates. Server-only code (anything importing `node:fs`) is limited to:
`lib/content/*`, `lib/menu.ts` (reads content), `lib/feed.ts` consumers, `lib/og.tsx`, `lib/editor/server/*`, `lib/redirects.mjs`, and the page bodies that call the content API during render.
Target: those calls move to route `loader`s; page bodies become components receiving props. `getMenuPreviews()` (root layout) becomes the root `loader`.
Markdown: `lib/content/render.tsx` today builds React elements at build time in the server component. New: `lib/content/render-hast.ts` (new file) runs the same unified/remark/rehype pipeline in the loader and returns the final hast (JSON-serialisable). The route component calls `toJsxRuntime` (`hast-util-to-jsx-runtime`, about 6 KB) with the same component map (`YouTube`, `Embed`, `Callout`, `Picture`, `Zoomable`, `PostPreviewLink`), moved into a small `lib/content/hast-to-react.tsx`. The toolchain (unified, remark, rehype, shiki, rehype-pretty-code, gray-matter) never reaches the browser. `render.tsx` stays in the tree for the dev preview until the final commit.
Cost: loader data is serialised twice (in HTML and as `.data`); measured in Phase 3 and compared to Next's RSC payload.
Navigation: `next/link` and `next/navigation` (`usePathname`, `useRouter`) are used in 28 files; all go through a new `lib/nav.tsx` adapter (`Link`, `usePathname`, `useRouter().push`). Components change one import line each; the old implementation stays selectable until switch-over.
`ReadingTheme` (inline script sets `data-reading` before paint) is unchanged: it renders a `<script>` in the page body; with prerendered HTML it executes during the first parse exactly like today. On client navigations, its layout effect still toggles the attribute.
`CardTransitions` calls `router.push` inside `document.startViewTransition`; React Router navigation is async (loader data fetch), so the update callback awaits `navigation` idle (via `router.navigate` promise) before resolving. Risk: high enough to get its own harness check (card to page transition fires, `data-vt` set/cleared).
`StrictMode` wrapper in layout is kept in `root.tsx`.
`next/script`, `next/dynamic`, `next/headers`: not used.

### 1.9 Build pipeline

Today `prebuild` runs `build-images`, `build-embeds`, `build-live-slugs`, `build-starlink`, then `next build`, then OpenNext. New `build` script:
`prebuild` unchanged, then `react-router build` (client + prerender), then `scripts/build-share-cards.mjs`, `scripts/build-worker-redirects.mjs`, `wrangler deploy --dry-run` bundles `worker/index.ts` (module Worker, `esbuild` via wrangler) with `assets.directory = build/client`.
`wrangler.jsonc`: `main` stays `worker/index.ts`; `assets.directory` becomes `build/client`; the self-service binding `WORKER_SELF_REFERENCE` is OpenNext's and is removed in the final commit; bindings `PRESENCE`/`REACTIONS`, migrations `v1`/`v2`, vars, cron and the Worker name `space` are not touched. Export names `PresenceRoom`/`ReactionsRoom` unchanged (`check:do` keeps guarding them; its source path stays valid).
Root scripts `build:michal`, `dev:michal`, `deploy:michal` keep their names. `preview` becomes `wrangler dev` on the built output.

### 1.10 CI and tooling

`.github/workflows/ci.yml` `build-michal`: `npm run build:michal` then `wrangler deploy --dry-run` (OpenNext step removed). `deploy.yml` `deploy-michal`: `npm run deploy:michal` = build + `wrangler deploy`. Composite actions (`setup`, `checks`, `media-cache`) unchanged (media cache paths stay). `scripts/smoke.sh` unchanged.
`.claude/launch.json` does not exist in the repo; entries for `vite dev` are added (`dev:michal` on port 3100 as scripts expect, `BASE` defaults in shoot scripts are 3100).
Scripts that assume `.next/`: `check-about.mjs --built` (reads `.next/server/app`; ported to read `build/client`), `glass-shots`, `article-shots`, `measure-type`, `build-resume-pdf` mention Next output or the dev server; they only need `BASE` to point at the new server and are updated where they touch `.next`.
Root guards (`check-dashes`, `check-identity`, `location-guard`, `type-guard`) skip `.next`/`.open-next`; `build` and `.react-router` are added to their skip lists.

### 1.11 Tests

`vitest` config (alias `@`, node env, `lib/**`, `components/**`, `worker/**`) is kept; no test imports Next at runtime (`next` only appears in types). `worker/*.test.ts` and `check:do` are source-level and unaffected. `lib/__tests__/seo.test.ts` is the oracle for the `Metadata` to `meta()` converter. New tests: route table (dev routes absent in production), redirects Worker, 404 behaviour, share-card determinism.

## 2. Key decisions

1. Framework mode, `ssr: false`, `prerender` as an async function returning every concrete path (pages, feeds, sitemap, robots, manifest, per-project feeds, the 404 page). SSR-at-build with a server bundle was rejected: nothing needs request-time rendering, and `ssr:false` deletes the server bundle (acceptance rule: no Node at runtime).
2. Loaders run at prerender in Node and import `lib/content` unchanged. Pages consume loader data; markdown is shipped as hast, rendered client-side by a thin converter.
3. Head tags via one `Metadata`-to-`meta/links` converter, tested against golden Next output, not hand-written per route.
4. Share cards are static PNGs produced by satori/resvg (same engine as `next/og`) in a build script, served by the Worker at today's URLs.
5. Worker is a plain module: redirects, host redirect, `/api/live/*`, `/globe/starlink-live.bin`, then `env.ASSETS.fetch`, then the prerendered 404. DOs and cron untouched; existing `worker/*.ts` files reused unchanged except `index.ts`.
6. Dev: `vite dev` through the RR7 plugin, dev routes appended to `routes.ts` in development; editor API as dev-only Vite middleware.
7. Keep `components/**` and `lib/**` byte-identical where possible; framework glue in new files (`app/root.tsx`, `app/routes.ts`, `app/routes/*`, `lib/nav.tsx`, `lib/head.ts`, `worker/index.ts`, `vite.config.ts`, `react-router.config.ts`). Next files (`app/**/page.tsx`, `layout.tsx`, `next.config.mjs`, OpenNext) are removed in the final commit only; until then new routes live in `app/routes/` and `app/` Next files coexist (Next ignores RR7 files outside its conventions and vice versa because RR7 only reads `app/routes.ts`).

## 3. Phases and gates

- Phase 1 (done first): parity harness in `scripts/parity/` and a baseline report generated from the golden Next build (`next build` of `origin/main`, served by `next start`).
- Phase 2: slices (root + home; then index pages; posts; feeds/sitemap; share cards; worker); harness run after each.
- Phase 3: full report, perf, wrangler dry-run and `wrangler dev` exercise, CI/docs, then delete Next/OpenNext (final commit).
- Hand back at the end of Phase 1 with plan and baseline.

## 4. Risks (ranked)

1. Visual parity from CSS ordering and font fallbacks (mitigated by pixel diff and CLS measurement).
2. `CardTransitions` timing under asynchronous RR7 navigation.
3. Client bundle growth because every component hydrates (manifest.json, markdown component map); measured against Next's per-route JS.
4. Head tag ordering and attribute differences between Next and RR7 (compared as sets, plus order for `<title>`, canonical, OG).
5. Share-card PNG determinism versus `next/og` output (pixel diff with tolerance).
6. Local sandbox: Node 22.3 (vite warns) and no `ps`/pid access; the harness avoids both.
