# AGENTS.md (apps/halmic)

Rules and traps for working on halmic.com. Read the repo-root [`AGENTS.md`](../../AGENTS.md) first (shipping, commits,
identity rule, agent environment). Human overview, commands and deploy: [`README.md`](README.md).

This file is scanned by `npm run check:identity` like the rest of the app. Do not add the owner's name, initials or the
portfolio domain to it. Describe the other site as "the portfolio".

## Shape

Zero runtime dependencies. `build.mjs` renders `src/index.html` plus `content/*.json` and markdown (`md.mjs`) into `public/`.
One small Worker (`worker/index.js`) answers `/api/*` only; everything else is served from `public/`. `serve.mjs` is the
local static server (port 4310, `PORT=` to change). The package depends on `@space/crosslinks` only.

## `public/` is a mix, and it is tracked

- Hand-kept sources: `base.css`, `bold.css`, `page.css`, `switcher.css`, `motion.css`, `app.js`, `hero.js`, `switcher.js`, `motion.js`, `vt.js`, fonts, images,
  `hero/*`, `previews/*`, `og/*`, `posts/*`.
- Generated by `build.mjs` (never hand-edit): every `*.html`, `404.html`, `sitemap.xml` (lastmod = build date), `rss.xml`,
  `robots.txt`, `llms.txt`, `_headers`, `icons.svg`, `previews/index.json`.
- Rules that follow:
  - After any change to `src/`, `content/`, `build.mjs`, CSS or JS, run `npm run build:halmic` and commit the output.
  - CSS and JS are linked as `?v=<content hash>`, so any CSS/JS change touches every HTML file. Two branches that both change
    them ALWAYS conflict in generated HTML. Resolve by merging `main`, taking either side of the generated files, re-running
    `npm run build:halmic` and committing. Never hand-merge generated files.
  - `sitemap.xml` changes on every build day; that diff is noise, not a bug.

## Page model

- Hero: inline SVG wordmark from `brand/wordmark-parts.json`, a status pill and a leaning-bar meter driven by `data-live` on
  `<html>`, and a WebGL highlights reel (`hero.js`, media in `public/hero/`, built by `brand/reel/`). The reel starts only
  after load, while the hero is visible and the tab is shown. A portrait cut serves phones. The poster (a baked render of the shader on one frame, `brand/reel/bake-poster.mjs`)
  is a TEMPORARY state except for reduced motion, data saver and no WebGL: a video error, refused autoplay, a source that decodes nothing for 8 s or a lost GL context show it, and the reel
  retries (back-off 3/6/12/24 s, and on resize, tab/scroll return and bfcache `pageshow`).
- Hero resize contract (`hero.js`): ONE path. A ResizeObserver on `.reel` (plus window `resize`, `orientationchange`, DPR change polled per frame) calls `onResize`, which only arms a
  timer; `settle()` runs 150 ms after the last event (at most 500 ms into a burst) and calls `layout()`. In between the canvas is just CSS-stretched and the fade zones are re-read per frame.
  `layout()` sets the canvas backing size (css size x `min(dpr, 2, 1920/width) x tier scale`), reallocates each render target ONLY when its own size changed (buffer, cell grid, wave field,
  which restarts still), and calls `swapSource()`, which changes `video.src` in place (portrait/landscape with hysteresis, 1080/720 with hysteresis): the GL pipeline stays, the last good frame
  stays on screen until the new source decodes. Never call `video.load()` outside `swapSource`, and never treat `play()` rejecting with `AbortError` as a failure (a swap or a pause interrupts it;
  that was the original bug). Frame times during a burst plus 900 ms after never count toward adaptive quality. The no-frame watchdog only counts while running and restarts on every swap.
- `node scripts/check-hero.mjs <url> [--desktop] [--mobile] [--auto] [--quick]` (headless Chrome with software WebGL, a running server, NOT in `npm test`): resize sequence (narrower, wider,
  desktop to phone and back, tall and short windows, orientation flip, a 20-size drag in 1 s, DPR changes, browser zoom), scroll away and straight back, lost and restored GL context, a bfcache
  `pageshow`, a swap flip-flop; after every step it asserts canvas backing size = css size x scale, the loop is advancing, the video plays the source the loop asked for, the hero is not in the
  poster state, and the console is clean. It reads `window.__reel` (only with `?reeldebug=1`): `frames state sc src qi resizes layouts swaps fallbacks reason lost`.
- Never edit the wordmark or anything in `brand/svg/`. They are generated geometry (`brand/build-logotype.mjs`).
- Below the hero are bentos: Watch (YouTube and Twitch mixed, round platform badges, the Special Force films lead), Play
  (Project Mountaintop leads), Work (Pokemon Phoenix Rising, the dental logo), Posts (`content/posts.json`; not rendered
  while empty), Elsewhere (X, Medium).
- Clusters: a bento is a stack of `.cl` groups (one project or kind of thing each, built by `cluster()` in `build.mjs`); each is its own packed grid, so
  another project's tile can never land inside it at any column count. Every tile declares its size at 4/3/2 columns (`SIZES` in `bentos.mjs`: one, w2, x4 = two wide only at 4 columns,
  lead = 2x2); the cluster's one `data-flex` tile gets the `fxC-N` classes (default width, so first paint has no holes) and `app.js` recomputes it.
- Arrangement is data: `bentos.mjs` is the model (sections, their clusters, each cluster's tiles with stable ids and default sizes, the flex tile, which tiles
  are required), `content/layout.json` is what the CMS changed (section order, titles and visibility; cluster placement, visibility, tile order, size and
  visibility), and `layout.mjs` applies one to the other and refuses arrangements that break the page (a hidden anchor section, a hidden required tile such
  as `#twitch` or `#hi`, a cluster without a flex tile that leaves a gap). `build.mjs` only maps tile ids to markup (`TILES`, `FLEX`). Add a tile by giving it
  an id and default size in `bentos.mjs` and its markup in `TILES`; do not put tiles directly in a bento. Keep tile ids stable: a saved layout names them. Year tiles (`yearTile`) read their year from content dates (video
  `published`, dev-log `date`); never type a year, and no dated source means no year tile. Clips are inserted before the Twitch tile in the Twitch cluster.
- Tile system: square-unit grid, sizes 1x1, 2x1, 2x2. Column count comes from the bento's own width (container query:
  4 from 880px, 3 from 640px, else 2). The single `data-flex` tile gets the width that fills the last row (`app.js`); a playing
  tile grows to 2x2. Stat tiles take their numbers from content (`stats.mjs`, re-derived by `check-links.mjs`), never typed in; a lone number gets a 1x1 or 2x1 tile (`x4`), never a stretched flex tile, and a cluster is balanced with sizes, not filler. Link tiles use brand colours; platform
  colours appear only on badges and link tiles. Click-to-play happens in place. Hover previews come from `public/previews/`.
- Labels are sentence case, no uppercase tracking (section `h2`, card eyebrows). A video tile names its kind in the caption (`Short film`), not a chip; the only chip on a tile is the duration.
- Spacing system (`base.css`, bento section): ONE rule set, no per-component insets. `:root` has `--gap` (tiles, 12/14/16px at 640/900), `--cgap` (2x, between clusters), `--sgap` (5x, between bentos), `--r` (radius of
  every tile, card and player) and `--r-in` (0.6x, small inner surfaces). Each `.tile` (and `.card`) derives from its OWN short side with `cqmin`: `--pad` (every inset: text left and bottom, numeral and brand mark ink left and top,
  badge top and left, chip, corner arrow and close button top and right, play disc bottom right), `--ctl` (height of badge, chip, corner button), `--tt-fs` / `--ts-fs`. A 2x1 tile has the short side of a 1x1, so they match; a 2x2 doubles. Never
  use `max(12px, 6.5cqi)` style insets on a component; use the tokens. Custom properties holding cq units are substituted where used, so use them only in a tile's children (they resolve against the tile). Optical alignment lives in
  tables: `.num[data-g]` (side bearing of the display face's first glyph, em) and `.lg[data-ic]` (empty margin of the brand mark, em); a new leading glyph or icon needs a row. `scripts/check-spacing.mjs` asserts all of it
  (box and ink positions, gaps, radius, one title size per tile size); run it with a server after any CSS change to tiles.
- Icons: `icon('name')` returns an inline `<use>` into the generated sprite. Sources are Phosphor Fill (MIT) and Simple Icons
  (CC0) under `brand/icons/`, with their licences. To add one, copy only that SVG from the npm package (fetched into a temp
  dir, never added as a dependency) into the matching folder, rebuild, use `icon('name')`. Unknown names throw at build time.
  The Noun Project is a style reference only: copy nothing from it (licence).
- Fonts: "Halmic Display" is generated by `brand/type/build-display.py`. `--ship` writes a content-hashed woff2 into
  `public/fonts/`, deletes the old one, and rewrites the URL and `unicode-range` in `base.css` and the preload in `build.mjs`.
  The hash changes on every rebuild, so only ship when the font really changed.

## Navigation chrome

- Switcher (`switcher.css`/`switcher.js`): on `(hover: none)` the first tap on the h opens a pill (Home, then the portfolio row) instead of going home
  (`aria-expanded`, `data-open`); second tap, tap elsewhere, scroll or Escape closes it. Hover-capable wide screens keep the hover dropdown. The pill reuses the
  existing header link, so the portfolio href and label still appear exactly twice per page.
- Page transitions: `@view-transition` in `base.css` (only with no reduced-motion preference). `vt.js` (head, not deferred, so `pagereveal` is not missed) names the
  clicked tile's picture and title `hero-media` / `hero-title` via the CSSOM on `pageswap`, and the tile returned to on `pagereveal`; destination pages carry
  `[data-hero]` (one per page) and `.pg h1`. Internal tiles/cards need `data-vt="m t"` (picture + title) or `"t"`. Names must stay unique per document.

## Motion

One motion language, in `motion.css` (everything new) and `motion.js` (observers, pointer, counters); `app.js` owns the live flip, player loader and clip swap. Tokens in `base.css` `:root`: durations
`--t1` 120ms (press, fades out), `--t2` 200ms (hover colour), `--t3` 360ms (moves), `--t4` 600ms (reveals, state changes); `--ease` (standard: fast start, long settle; the only curve, no overshoot or spring). Use them; no literal durations in new CSS.
No hover zoom on pictures, no picture parallax, no glyph tilt (removed in the unslop pass; keep it that way).

- Gates. `vt.js` (head) sets `html.js` always, `html.mo` only when there is no reduced-motion preference and no `?motion=0`. Anything that hides something until a reveal needs `.mo`, so no scripts or reduced motion shows the plain page
  (a test asserts it). `?motion=0` (not linked) also sets `data-motion="0"`, which kills every animation and transition; `check-spacing.mjs`, `check-holes.mjs` use it so transforms never skew measurements.
- Never touch scrolling: no wheel, touch or scroll-position code, no snapping, no smooth-scroll script. Scroll only drives progress (CSS timelines, IntersectionObserver). `html { scroll-behavior: smooth }` for anchors only
  under no-preference; `scroll-padding-top: var(--hdr)` because the header is fixed with scripts (`.js .top`). Programmatic scrolls in tools must pass `behavior: 'instant'`.
- Scroll-driven (CSS `animation-timeline`, in `@supports`, `.mo` only; browsers without them get a one-shot `.rv` then `.in` reveal from `motion.js` for what starts below the fold, and none of the hand-off, hairline or progress bar):
  tile and card entrance (`view()`, staggered by `--i` from `nth-child`; it reverses on scroll back up because a view timeline is position driven),
  section label slide and hairline (named `--sec` timeline on each `.bsec`), hero hand-off (`--hero` timeline on `.hero` with `timeline-scope` on `body.home`: wordmark settles, bars drift, header backdrop arrives), top progress hairline
  (`scroll(root)`), dev-log figures, callouts and videos rise, `h2` marker draws. Tiles are `overflow: clip` (not hidden) so `view()` inside them still sees the viewport as its scroller.
- JS micro-interactions (`motion.js`): header `.solid` backdrop toggle, tile sheen and 2.5 degree tilt (hover-capable fine pointers, one rAF-throttled delegated `pointermove`, CSS variables `--mx --my --rx --ry`), press state
  (`.is-press`, any pointer), nav marker (slides on hover or focus, rests under the current section; scroll-spy by IntersectionObserver sets `aria-current`), numeral count-up (restores the exact static text; years roll from year minus 8).
- CSS only: arrow loop on `.goi` (two arrows in `GO`; the second slides in), play-disc ring, chip glide, link-tile lift, button lift and squash, arrow-down bob, animated focus ring, close button scale, players' buttons rise in.
- `app.js`: live flip pulses the status pill (`.flip`) and kicks the meter springs; a player shows a spinner disc (`.pload`) until the iframe's `load`, then the iframe fades in; a closed player returns the tile with a fade (`.back`);
  clips arriving from `/api/clips` get `.clip-in` (content fades in, staggered; badge pops; picture fades in on load).
- Not done on purpose: no scroll velocity in `hero.js`, no pinned scenes, no same-document anchor fade (native smooth scroll already does the job).
- `node scripts/check-motion.mjs <url>` asserts: no wheel or touch listeners, a real wheel input moves the page by its delta, synthetic wheel and touchmove are not default-prevented, no animation under reduced motion or `?motion=0`,
  everything visible with scripts off, no layout shift or horizontal overflow while scrolling at 1440/390/360, no long task in the best of three runs with the hero reel off (`nogl`; software rendering is noisy, and the reel starting up logs long tasks on the page without any motion code), numerals end on their static text.

## Content security policy (strict, generated in `build.mjs`)

`_headers` carries the CSP. Consequences for any change:

- No inline `<style>`, no `style="..."` attributes, no inline scripts. JS may set styles through CSSOM
  (`el.style.x = ...`). JSON-LD is a data block, which is allowed.
- Third parties are exactly: `static.cloudflareinsights.com` (script) and `cloudflareinsights.com` (connect) for Cloudflare Web
  Analytics, which the owner wants; frames from `www.youtube-nocookie.com` and `clips.twitch.tv`. `media-src 'self'`.
- Nothing else is requested from other hosts. Thumbnails, box art, post images, icons and fonts are local or proxied by the
  Worker. If you need a new external request, stop and ask.
- `scripts/check-links.mjs` (part of `npm test`) enforces several markup rules (no inline styles, local images, one h1, alt and
  sizes, resolvable links and icons, size budgets for previews).
- The only local way to exercise the real CSP and the Worker together is `wrangler dev` (see below). `serve.mjs` sends no CSP.

## Worker (`worker/index.js`)

- `/api/live`: Twitch Helix with an app token, edge-cached 45 s. `/api/clips`: top clips, cached 1 h. `/api/clip-thumb/<id>`
  and `/api/game-art/<id>`: same-origin image proxies, restricted to ids from the cached clips payload.
- Secrets `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` are set by the owner with `wrangler secret put`. Agents never handle
  the values. Without them the endpoints answer an "unknown" payload.
- Failures return an "unknown" payload, never a 5xx.
- Never call the global `fetch` through an object property (`deps.fetch(...)`): workerd throws "Illegal invocation". The code
  wraps it (`(...a) => fetch(...a)`). Unit tests inject a fake fetch, so they do NOT catch this regression.
- Cloudflare's zone Browser Cache TTL rewrites `max-age` on API responses to hours for browsers. The client therefore fetches
  `/api/*` with `cache: 'no-store'`. Keep it.
- Worker logs: Cloudflare dashboard, Workers, halmic, Observability.
- `workers_dev` and `preview_urls` are off in `wrangler.jsonc` on purpose; custom domains come from `routes`.

## Identity rule, applied here

The root guide has the rule and its exceptions. Practical points for this app:

- Run `npm run check:identity` before every commit that touches `src/`, `content/`, `public/`, `worker/` or `brand/`.
- `scripts/sync-youtube.mjs` holds back any video whose title or description trips the local deny list, writing it to
  `content/videos.held.json`. Do not publish held entries without the owner. `content/identity-denylist.txt` is that script's
  copy of the patterns; do not print or edit it.
- Posts: links to the owner's own X posts pass the check only in the exact status-URL form the library exempts. Never write
  the account handle as text.
- Media (video thumbnails, `hero/`, `previews/`, `posts/`, `og/`, `shots/`): view the frames. Known hazards: FIFA episode
  HUD cards with a surname, Special Force name credits, Twitch overlays with a handle. Crop them out or skip the item.

## Media pipelines

Only the owner's own published content is used (his YouTube channel, his Twitch clips). Sources are fetched with `yt-dlp` in a
venv under `$TMPDIR` and never enter the repo; only rendered outputs are committed. EDLs and scripts make them reproducible:
`brand/reel/` (hero reel, see its README) and `brand/previews/` (hover previews). Size budgets are enforced by
`check-links.mjs`. Keep `apps/halmic/shots/` small: JPEG, and delete superseded sets.

## CMS (docs/cms.md)

- The editor edits `content/layout.json`, `content/curation.json`, `content/posts.json` with `public/posts/`, and the Mountaintop dev logs
  (`content/mountaintop/` with `public/work/mountaintop/`). Their source of truth is the private content repo's `halmic/` folder; CI lays it in with
  `npm run content:pull` (`scripts/content/pull.mjs`) before building, and a checkout without that folder leaves this repo's copies in place.
- `content-rules.mjs` is what an edit may contain (pure; the editor imports it too). `npm run content:check` runs it plus the identity denylist over the
  editable files, and `npm run build` runs it first. A new field in one of those files needs a rule, or the check rejects it.
- `scripts/check-links.mjs` checks that the home page follows `layout.json` whatever it says; its editorial checks (which film leads, game order, the stat
  tiles) only run for the default arrangement.
- Never write the content repo's name or its other site into anything under `apps/halmic` except `docs/`: the identity check scans the rest.

## Test and verify

```bash
npm test -w @space/halmic        # worker tests (node --test), check-links.mjs, check-social.mjs --dir public
npm run content:check -w @space/halmic   # the CMS-editable content against content-rules.mjs and the identity denylist
npm run check:identity           # from the root
node apps/halmic/scripts/check-social.mjs https://halmic.com --ua=Twitterbot/1.0   # live social-card audit
npm run og -w @space/halmic      # rebuild public/og/*.jpg share cards (needs Chrome and sharp)
PORT=4563 node apps/halmic/serve.mjs &
node apps/halmic/scripts/check-holes.mjs http://localhost:4563   # bento packing; needs Chrome and a running server; NOT in npm test
node apps/halmic/scripts/check-spacing.mjs http://localhost:4563  # one spacing system, at 1440/1024/768/390; same needs; NOT in npm test
node apps/halmic/scripts/check-motion.mjs http://localhost:4563   # scroll integrity, reduced motion, no-JS, long tasks, CLS; same needs; NOT in npm test
node apps/halmic/scripts/check-hero.mjs http://localhost:4563     # hero reel survives resizing, zoom, DPR, context loss; same needs; NOT in npm test
```

- `scripts/shot.mjs <url> <out> <w> <h> [flags]` takes headless Chrome screenshots over CDP. Flags: `full`, `mobile`, `jpg`,
  `gl` (software WebGL, needed to see the reel), `nogl`, `rm` (reduced motion), `eval=<js>`, `click=<css>`, `hover=<css>`,
  `netlog`, `console`, `nojs` (scripts disabled), `wheel=<dy>` (a real wheel event, prints scrollY before and after), `tap=x,y` + `strip=ms,ms,...` (touch the hero and save timed shots), `clip=x,y,w,h`, `sel=<css>`, `resize=WxH[xDPR][zZOOM][@ms],...` (apply sizes after the wait; zoom shrinks the css size and grows the device ratio like browser zoom) with `rshots` (a shot after each, `<out>-r<i>`) and `rwait=ms`, a bare number for wait in ms. Chrome comes from `CHROME_PATH` or the macOS default;
  `ws` and `sharp` resolve from the root `node_modules`.
- Test overrides (not linked from the UI): `?live=1&game=<name>` forces the on-air look, `?live=0` offline;
  `?clips=demo&n=0..6` fake clips, `?clips=none` none; `?reelq=0..3` pins the reel quality; `?reelfx=0` turns off the hero's wave field, idle flow and touch/pointer input (A/B against the plain glyph screen); `?reelhf=0` forces the RGBA8 (no half-float) field path; `?motion=0` turns every animation and transition off and leaves the DOM as built (use it for any measurement); `?reelclock=frame` (with `reelq`) advances effect time one tick per rendered frame, which `shot.mjs tap=x,y strip=0,150,500` uses to photograph a ripple on slow software GL; `?reeldebug=1` exposes `window.__reel` (frame counter, state, canvas scale, source, swaps, fallbacks; used by `check-hero.mjs` and `bake-poster.mjs`).
- `.claude/launch.json` (local, gitignored) can run `halmic` (`npm run dev:halmic`, port 4310) and `halmic-worker`
  (`wrangler dev --cwd apps/halmic --port 8788`, the real `_headers` and Worker).
- Social cards: `scripts/build-og.mjs` writes `public/og/*.jpg`; `check-social.mjs` audits OG/Twitter tags and images for every
  sitemap URL, locally or live.
